# Как помочь

Спасибо, что заглянули. Здесь собраны нормы о паллиативной помощи с дословными цитатами и калькулятор сроков. Любая ошибка в цитате или сроке может подвести семью, поэтому правим только по официальным текстам и только после проверки человеком

*English: see the short section at the end*

## Сначала о приватности

Issues и PR открыты всем и остаются в интернете навсегда. Не пишите ФИО, диагнозы, адреса, телефоны, номера полисов и документов, не прикладывайте сканы своих выписок, писем и ответов ведомств. Даже если хотите показать, как было на самом деле. Для ошибки в норме нужна только норма

Проект не ведёт списки подопечных и не принимает обращения о конкретных людях. Если человеку плохо прямо сейчас, звоните **112** или **103**

## Нашли ошибку в цитате

Откройте issue по форме «Ошибка в цитате» и укажите:

1. где на сайте ошибка (адрес страницы или id цитаты из `data/v1/quotes.json`)
2. ссылку на официальную публикацию на [publication.pravo.gov.ru](http://publication.pravo.gov.ru) (адрес вида `http://publication.pravo.gov.ru/document/<eoNumber>`)
3. номер страницы скана, на которой стоит цитата
4. как написано в публикации, дословно

Пересказы, тексты из справочных систем, сайтов ведомств и НКО как источник цитаты не подходят. Если официального текста в нужной редакции нет, цитата остаётся «Не проверено», так честнее

## Нашли ошибку в сроке

Форма «Ошибка в сроке»: какой срок, какую дату события вы ввели, какую дату показал сайт, какая должна быть и почему. Толкования сроков пока не проверены юристом в РФ, поэтому особенно ждём юристов

## Хотите предложить норму

Форма «Новая норма». Берём только акты с официальной публикацией. Письма ведомств и разъяснения не берём

## Если пишете PR

Данные лежат в YAML в `data/`, цитаты в `data/quotes/<акт>.yaml`. У каждой записи есть `verified`, источник и дата сверки. Порядок такой:

1. новая или исправленная цитата: eoNumber, номер страницы, текст дословно по скану, вырезка скана в `raw/crops/<id>.png`
2. пока человек не сверил запись со сканом, `verified: false`, на сайте это видно
3. `sh scripts/gate.sh` проходит: схемы, ссылки между наборами, тесты сроков, сборка, проверка текста, браузерные тесты
4. в PR ссылка на публикацию и страницу скана

Статусы актов, цитаты, правила сроков, ступени «если не ответили» и показания сами не меняются никогда, в том числе наблюдателем. Только PR с ревью человеком. Метка `review:data` для данных, `review:legal` для толкований

Чего не делаем:

- не правим `opsite/` в этом репо: это копия общего UI из хаба [openpalliative.github.io](https://github.com/openpalliative/openpalliative.github.io), правки туда, потом `sh scripts/sync-ui`
- не добавляем аналитику, трекинг, внешние шрифты и запросы к другим сайтам из браузера
- не пишем медицинских советов, доз, порогов и названий препаратов
- не добавляем учёт подопечных, обращений и любые функции CRM

## Кто нужен

- **Юрист в РФ:** проверить толкование сроков и ступеней (`data/deadline-rules.yaml`, `data/escalation.yaml`). После проверки в `data/review/` появляется запись, и плашка «Толкование не проверено» снимается
- **Врач паллиативной помощи:** посмотреть, как показаны показания (`data/indications.yaml`). Страница `indications/` на сайте закрыта, пока её не проверят медик и юрист
- **Человек в РФ с доступом к системе «Законодательство России»:** сверить 59-ФЗ и статьи ГК с живой системой
- **Мейнтейнер в РФ:** разбирать issues наблюдателя раз в месяц

## Тексты

Пишем просто, для человека в стрессе и пожилого: короткие фразы, без канцелярита. Без длинных тире, только короткий дефис. Без эмодзи. Проверка `uv run python -m opsite check` ловит часть ошибок сама

## English

This repository publishes Russian palliative care regulations as open data with verbatim quotes from the official publication portal publication.pravo.gov.ru, plus a deadline calculator. To report a wrong quote or deadline, open an issue with a link to the official publication and the scan page number. Never post names, diagnoses, addresses, phone numbers or document numbers: issues are public. Pull requests must keep `verified: false` until a human checks the record against the scan, and must pass `sh scripts/gate.sh`. Do not edit `opsite/` here, it is synced from the hub repository. Security issues go through private vulnerability reporting, see SECURITY.md

# pal-norms: архитектура

Срез 11.10.2026. Репо `pal-norms`, префикс `pn`, порт 8701, на Pages `/pal-norms/`. Название для людей «Нормы и сроки», иконка `scale`

Основа: `../PLAN.md` (D1-D10), `../PLATFORM.md` (стандарт), `../UX_MAP.md` (адреса, тексты, переходы), итоговый план проекта (идеи 5 и 7). Здесь только решения поверх них. Где этот файл молчит, действует PLATFORM.md

Уже лежит в репо (пишет ARCH, дальше владеет DATA):

- `data/schema/*.schema.json`: 8 схем публикуемых датасетов. Это контракт между DATA и SITE
- `tests/fixtures/*.json`: синтетические конверты по этим схемам, все id с префиксом `demo-`. На них SITE строит сайт, пока нет настоящих данных

## 0. Коротко

- Сайт открывается от задачи, а не от номера акта: «Посчитать срок», «Если не ответили», «Показания», «Все документы». Номер акта везде мелкой строкой под человеческим названием
- Факты (реквизиты, eoNumber, статус по тексту отмены, дословные цитаты) живут без юриста. Толкования (с какого события считать, кто обязан, куда жаловаться) публикуются только с пометкой «Толкование не проверено юристом в РФ»
- Два уровня проверки вместо одного: `verified` значит «текст сверен со сканом официальной публикации», `legal_review` значит «толкование проверил юрист». Иначе fail closed парализует потребителей: юриста в РФ пока нет
- Наблюдатель сам коммитит только служебный снимок `data/snapshots/`. Всё, что видят семьи, приходит через PR или issue
- Календарь рабочих дней ведём сами из постановлений о переносе выходных с eoNumber (PLATFORM, добавка 2). `prodcalendar` только сверяет 2025-2026 в тестах
- Своего OCR-корпуса не строим (решение итогового плана): полные тексты OCR лежат только в `raw/cache/` (в .gitignore), в репо попадают цитаты, вырезки скана под ними и sha256 PDF

## 1. MVP и позже

### 1.1 MVP (один прогон)

- **Акты.** Не меньше 15 записей с реквизитами из API и `verified:true`, всего до 30. Список кандидатов в разделе 3.3
- **Цитаты.** Только пункты, на которые опираются статусы, сроки, показания, ссылки на отменённые акты и правила проверки текста. Примерно 40-70 цитат, каждая с вырезкой скана
- **Сроки.** 8-12 правил. В данные идёт только правило с дословной цитатой, где стоит число и единица. Правило без найденной цитаты остаётся в `data/candidates.yaml` и не публикуется
- **Эскалация.** 3 ступени: «срок прошёл, ответа нет», «жалобу переслали тем, на кого жаловались», «есть угроза жизни: подать параллельно». Все с `legal_review: none`
- **Показания.** Взрослые (п. 4, прил. 1 целиком) и дети (п. 5), плюс п. 2, «перечень не является исчерпывающим», кто выдаёт заключение (п. 12, 13, 15)
- **Календарь.** Базовые праздники по ст. 112 ТК и переносы на 2025, 2026, 2027 годы из ПП 1335, 1466, 1187
- **Проверка текста.** 6 правил: 345н/372н, 187н и 193н → 208н/243н; 348н → 398н; 502н → 180н (если в 180н найдена отмена); ПФР и ФСС → СФР; «30 рабочих» рядом с «18 лет» → п. 23. Один эталонный корпус для `lib/textcheck.js` и `tools/pack_lint.py`
- **Лента изменений.** Только реальные события с eoNumber, все в состоянии `accepted`: ПП 1187 о переносах на 2027 год, вступление 208н/243н, 398н, 180н, публикация 692н и другие найденные по API
- **Наблюдатель.** Код, тесты на записанных ответах API, `watch.yml`. В CI в этом цикле не запускается (ничего не пушим)
- **Сайт.** 13 видов страниц из раздела 2, калькулятор срока, проверка текста, печать A4, работа без JS, светлая и тёмная темы

### 1.2 Позже

- Наблюдатель regulation.gov.ru (проекты) и apicr (клинические рекомендации старше 3 лет)
- `review-sheet` (печатный лист для юриста: цитата, вырезка скана, вопросы «верно / неверно / не знаю») и `review-ingest`
- Atom-лента `/changes/changes.xml`
- Релизы SQLite и Zenodo с DOI
- Таблица бланков рецептов и сроков (C31), реестр законов о возмещении (C14), домены `bereavement`, `social`, `links.yaml`
- Правила проверки текста, которые сами собираются из `aliases` и `superseded_by` (в MVP правила явные, а тест следит, чтобы у каждого отменённого акта с `aliases` было правило)
- Региональный слой: только PR от физлиц со ссылкой на официальную публикацию, после решения мейнтейнера в РФ

### 3.2 Схемы и поля

Точные схемы лежат в `data/schema/<name>.schema.json` (JSON Schema 2020-12, без `$ref`, чтобы работало `opsite.data.coerce`). Ниже смысл полей

**`acts`**

- `id`: стабильный слаг (`208n-243n`, `59-fz`, `pp-1187`). Год в конце (`505n-2019`) только если номер повторяется внутри `acts.yaml`
- `kind`: `federal_law | code | government_decree | government_order | ministry_order | joint_order`
- `authority`, `number`, `doc_date`, `title` (поле `name` из API), `short_title` (человеческое название, его выводит `norm()`), `topics[]`
- `eoNumber` (16 цифр или пусто), `publish_date`, `pages`, `url` (`http://publication.pravo.gov.ru/document/<eo>`), `pdf_url` (`http://publication.pravo.gov.ru/file/pdf?eoNumber=<eo>`), `pdf_sha256`
- `text_source`: `official_pdf | ips_archive | none`; `alt_source` для ИПС: `nd`, `snapshot_url`, `sha256`, `retrieved_at`
- `status`: `in_force | not_yet_in_force | repealed | draft | unknown`; `status_basis {act_id, point, quote_id}` обязателен у `repealed`
- `in_force_from`, `valid_until` (срок действия по «гильотине», только с цитатой), `repealed_at`
- `supersedes[]`, `superseded_by[]` (симметричны), `amended_by[{eoNumber, doc_date, title}]`
- `cites[{act_id, point, quote_id}]`: ссылки, видимые в тексте. `cites_repealed` и `rule_ids` вычисляет export
- `aliases[]`: написания для поиска и проверки текста («345н/372н», «345н»)
- `quote_ids[]`, `review {status, role, reviewed_at, expires_at, ref}`, `notes`
- общие: `verified`, `verified_at`, `source_ref`

**`quotes`**: `id` (`208n-243n-p23`), `act_id`, `point` («п. 23», «прил. 1, п. 2», «ч. 1 ст. 12»), `anchor` (`p-23`, `p-a1-2`, `p-12-1`), `page` (страница PDF), `text` дословно, `text_source`, `ocr {passes, diff_lines, dpi[]}`, `scan_checked {at, method, crop}`

**`deadline-rules`**: `situation`, `result_label`, `from_event` (код) и `from_event_label`, `who`, `value`, `unit` (`calendar_days | working_days | within_24h`), `direction` (`forward | backward`), `pre {value, unit, label}` (3 дня на регистрацию), `extension` (продление по ч. 2 ст. 12 59-ФЗ), `shift_if_nonworking` (`yes | no | unknown`), `margin_working_days` (запас для обратного счёта, 5 у п. 23), `norm_ids[]`, `quote_ids[]` (минимум одна), `ambiguous`, `ambiguity_note`, `escalation_ids[]`, `audience[]`, `legal_review`

**`calendar`**: item `baseline` (`holidays_mmdd[]`, `carry_over`, `carry_exclude_mmdd[]` для январских, `quote_ids`) и item на год (`year`, `decree_act_id`, `decree_eoNumber`, `transfers[]`, `off[]` все нерабочие дни кроме обычных суббот и воскресений, `work[]` рабочие субботы и воскресенья, `quote_ids`). Год `verified` только если проверены постановление, его цитата и базовые праздники

**`escalation`**: `order`, `trigger` (`no_answer_after_due | redirected_to_accused | answer_not_on_merits | threat_to_life`), `title`, `what`, `addressee_kind` (только тип органа), `parallel`, `norm_ids[]`, `quote_ids[]`, `rule_ids[]`, `ok_doc`, `legal_review`

**`indications`**: `audience` (`adults | children`), `section` (`scope` п. 4 и п. 5 Положения, `general`, `rule` п. 2, `group`, `decision` п. 12, 13, 15), `group_id`, `group_title` (дословный заголовок пункта группы), `order`, `act_id`, `point`, `anchor`, `page`, `text`, `text_source`, `ocr`, `scan_checked`

Диалект регулярных выражений общий для JS (флаг `u`) и Python `re`: классы символов, альтернативы, квантификаторы, просмотр назад только фиксированной длины. ### 3.4 Парсинг (`pipeline/`)

- `pravo.py`: клиент API. `urllib.request`, `User-Agent: openpalliative-watch (+https://github.com/openpalliative)`, один запрос за раз, пауза 2 с между запросами, таймаут 30 с, 4 попытки с паузами 2, 4, 8, 16 с. `PageSize` проверяется по списку 10, 30, 100, 200. Разбор ответа в dataclass, неизвестная форма ответа = исключение `SourceFormatError`
- `fetch_pravo.py`: `uv run python -m pipeline.fetch_pravo <act_id>|--all`. Метаданные в `raw/meta/<eo>.json` (коммитятся, около 2 КБ), PDF в `raw/cache/<eo>.pdf` (не коммитится), строка в `raw/SOURCES.tsv`: `eoNumber, url, sha256, bytes, retrieved_at`
- `ocr.py`: только нужные страницы. Проход A: `pdftoppm -r 300 -gray` и `tesseract -l rus --psm 4`. Проход B: `-r 400` и `--psm 6`. Нормализация для сравнения (NFC, пробелы, перенос слова через дефис в конце строки). Разница строк в `raw/ocr-diff/<quote_id>.diff`. Вырезка скана под цитатой по координатам из `tesseract ... tsv` в `raw/crops/<quote_id>.png` (оттенки серого, до 150 КБ). Полный OCR страниц только в `raw/cache/ocr/`
- `quotes.py`: `uv run python -m pipeline.quotes add <act_id> <page> "<начало>" "<конец>"` вырезает фрагмент между маркерами из прохода A, пишет черновик цитаты в `data/quotes/<act_id>.yaml` с `verified:false`, делает вырезку и diff
- `fetch_ips.py`: CDX web.archive по `nd`, последний снимок с `id_`, cp1251, вырезка статьи по заголовку, sha256 снимка в `alt_source`. Всегда `verified:false`
- `calendar.py`: из `holidays.yaml` и `transfers.yaml` строит `off` и `work` по годам. Правило ч. 2 ст. 112: праздник в субботу или воскресенье переносится на следующий рабочий день, кроме январских, которые переносит постановление
- `export.py`: `datasets(root) -> list[dict]`. Собирает конверты через `opsite.data.make_envelope`, считает `cites_repealed`, `rule_ids`, `off/work`, сливает `review/`. С `PN_FIXTURES=1` возвращает `tests/fixtures/*.json` как есть (для SITE до данных и для e2e на синтетике)
- `watch.py`: раздел 5

### 3.5 Проверка и пометки

| Уровень | Что значит | Кто ставит | Условие |
|---|---|---|---|
| цитата `verified` | текст совпадает со сканом официальной публикации | DATA при подготовке, позже мейнтейнер | `text_source: official_pdf`, два прохода OCR, расхождения разобраны по вырезке, `scan_checked` записан, вырезка лежит в `raw/crops/` |
| акт `verified` | реквизиты совпадают с API, статус подтверждён | DATA | метаданные из API, поиск `от ДД.ММ.ГГГГ № N` выполнен в дату `verified_at`, у `repealed` проверенная цитата-основание. Акты `ips_archive` и `none` (кроме отменённых по цитате другого акта) всегда `false` |
| правило срока `verified` | число и единица стоят в проверенной цитате | DATA | все `quote_ids` проверены, `value` встречается в тексте цитаты (pytest), нормы `in_force` |
| год календаря `verified` | постановление и праздники сверены | DATA | цитаты ПП о переносах и 35-ФЗ проверены, совпадение с `prodcalendar` за 2025-2026 |
| строка показаний `verified` | как цитата | DATA | как цитата |
| `legal_review.status: ok` | толкование проверил юрист в РФ | только мейнтейнер через `review/*.yaml` и CODEOWNERS | в MVP везде `none` |

Чего нельзя: `verified:true` у цитаты из ИПС, у акта без eoNumber (кроме отменённого по проверенной цитате), у правила без цитаты. Если расхождение OCR не удаётся разобрать по вырезке, цитата остаётся `verified:false`. Медицинские пороги из приказа (например, «потеря массы тела более чем на 10%») показываются только дословно в `<blockquote data-verbatim>`, без пересказа. Из 100н и 1094н не берём перечни препаратов и бланков, только сроки и порядок

### 4.3 Интерфейсы кода

```js
// lib/deadlines.js, без DOM и сети
computeDeadline({ rule, start, calendar })
// rule: элемент deadline-rules; start: "YYYY-MM-DD"; calendar: конверт calendar
// -> { rule_id, due, due_alt, latest, formula, steps: [{ label, date }],
//      norm_ids, ambiguous, verified, calendar_verified, margin_applied }
isWorkingDay(iso, calendar)            // -> { working, verified }
addWorkingDays(iso, n, calendar)       // n может быть отрицательным
nonWorkingDays(fromIso, toIso, calendar) // -> [{ date, kind: "weekend" | "holiday" | "transfer" }]
calendarYears(calendar)                // -> { 2027: { verified } }
```

- Календарные дни считаются со следующего дня после события. `pre` прибавляется первым. `within_24h` даёт следующий календарный день
- `shift_if_nonworking: yes` переносит срок на ближайший рабочий день, `unknown` оставляет `due` без переноса и кладёт перенесённую дату в `due_alt`, `latest` = более поздняя из двух
- Обратный счёт: `due` = рабочий день, до которого от него до события (не включая день события) ровно `value` рабочих дней. Если хоть один год в диапазоне не `verified`, вычитается ещё `margin_working_days`, `margin_applied` > 0
- Вне известных лет: выходные и праздники `baseline` с переносом по ч. 2 ст. 112, `calendar_verified:false`
- `formula`: строка по-русски («30 дней со дня регистрации, 3 дня на регистрацию»), без номеров актов

```js
// lib/textcheck.js
normalize(text)                       // NFC, пробелы, «№»
checkText(text, rules, { acts })
// -> [{ rule_id, kind, severity, line, col, start, end, fragment, context, message,
//       act_id, suggest_act_id, quote_ids }]
```

```sh

python3 tools/pack_lint.py <файлы или папки> --rules lint-rules.json --acts acts.json [--json]
# выход 1, если есть находка severity: error или norm('id') на неизвестный, не in_force или не verified акт
```

### 5.2 Наблюдатель `pipeline/watch.py`

`uv run python -m pipeline.watch [--fixtures DIR] [--report _reports/watch.json] [--apply]`

1. **Канарейка.** `GET /api/Document?eoNumber=0001202505290031`: есть ключи `eoNumber, number, documentDate, pagesCount, name`, `pagesCount == 196`. `Documents?PageSize=30&Name=паллиативной` даёт `itemsTotalCount > 0`. Не прошла: ничего не меняем, в отчёт `source_format`. Сеть не ответила: `consecutive_failures += 1`
2. **Отслеживаемые акты.** Для каждого акта с eoNumber: `Name=от ДД.ММ.ГГГГ № N` по блоку органа. Найденный eoNumber, которого нет ни в `acts.yaml`, ни в `amended_by`, ни в `seen`, даёт `review` вида `amendment_or_repeal`
3. **Тематический поиск.** `Name` по словоформам «паллиативной», «паллиативная», «паллиативную», «паллиативных» в блоках `president`, `government`, `federal_authorities`, `PublishDateFrom = last_ok_at - 14 дней`. Новое даёт `new_act`
4. **Переносы.** `Name=О переносе выходных дней`, `Block=government`. Новый eoNumber даёт `transfer_decree`: скачать PDF, OCR, черновик года в `data/calendar/transfers.yaml` с `verified:false` и запись в `data/changes.yaml`
5. **Срок действия.** `valid_until` ближе 120 дней даёт `sunset_soon`
6. **Снимок.** `data/snapshots/watch-state.json`: `checked_at`, `last_ok_at`, `consecutive_failures`, `seen {eo: {pagesCount, pdfFileLength, publishDateShort}}`, `queries {имя: {total, last_eo}}`. Изменение `pagesCount` или `pdfFileLength` у известного акта даёт `review` вида `republished`

С `--apply` (только в Actions или у мейнтейнера):

- **Коммитится само:** только `data/snapshots/watch-state.json`, сообщение `data: снимок pravo.gov.ru <дата>`. После коммита `gh workflow run pages.yml`: пуш токеном Actions сам Pages не запускает. Расписание коммит не держит, поэтому последний шаг с `if: always()` делает `PUT .../actions/workflows/watch.yml/enable`
- **PR** (`peter-evans/create-pull-request`, ветка `watch/<дата>`): черновик года календаря и запись ленты (метка `review:data`), затем `gh workflow run checks.yml --ref watch/<дата>`. Мерж PR = событие принято
- **Issue** (`gh issue create`, заголовок `[watch:<sha8>] ...`, где sha8 от `kind + eoNumber`; дубли ищутся по заголовку среди открытых и закрытых): `new_act`, `amendment_or_repeal`, `republished`, `sunset_soon`, `source_format`, и «Наблюдатель не достучался до pravo.gov.ru» при `consecutive_failures >= 3`
- **Никогда само:** `status`, `superseded_by`, цитаты, правила, показания, эскалация, правила проверки текста. Только PR с меткой `review:legal` и ревью человеком

Запасной путь, если pravo.gov.ru не пускает раннеры GitHub: `scripts/watch-local` раз в месяц у мейнтейнера (с его компьютера API отвечает), тот же отчёт и те же PR через `gh`. В README: «6 месяцев без ревьюера - архив», релиз zip для зеркала

`data_date` в `meta.yaml` правит человек после сверки записей. Дата последнего прохода наблюдателя показывается отдельно и `data_date` не обновляет
